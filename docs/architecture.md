# 系统架构与核心逻辑

## 1. 组件职责

| 组件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| MaxKB | 接收问题、维护会话、检索知识、选择工具、生成回复 | 不保存模拟订单的业务规则 |
| 售后知识库 | 保存退换货政策、运费规则和常见问题 | 不提供实时订单状态 |
| MCP 工具服务 | 校验用户、查询订单和物流、计算退款资格 | 不生成开放式自然语言答案 |
| 模拟订单数据 | 为课程演示提供固定、可复现的数据 | 不连接真实商城和真实用户 |

## 2. 一条主流程

1. 用户在 MaxKB 中输入问题。
2. MaxKB 的 AI 节点识别问题需要“知识”还是“业务数据”。
3. 政策问题检索知识库；订单类问题调用 MCP 工具。
4. 工具服务先校验订单号与手机号后四位，再执行确定性的查询或计算。
5. 大模型将检索内容或工具结果整理成自然语言回复。
6. 回复中明确给出结果、原因和下一步操作。

## 3. 三个最重要的答辩概念

### RAG

RAG 是“先检索、再生成”。售后规则不要求模型背下来，而是先从我们上传的文档中找到相关片段，再根据片段回答，从而减少编造。

### Agent 工具调用

大模型根据工具名称、说明和参数决定是否调用工具。工具内部仍是普通 Python 代码，所以订单校验和退款规则能够被单元测试验证。

### MCP

MCP 是大模型应用连接外部工具的标准协议。本项目的 Python 服务通过 Streamable HTTP 暴露工具，MaxKB 只需配置一个 `/mcp` 地址即可发现并调用这些工具。

## 4. 为什么不直接让大模型判断退款

退款资格属于确定性业务规则。如果只写在提示词里，大模型可能漏掉条件或产生幻觉。因此，本项目把规则放在 Python 服务中，大模型只负责理解用户意图和解释计算结果。
